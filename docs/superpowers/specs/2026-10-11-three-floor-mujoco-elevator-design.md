# 三层开放房屋与可交互电梯场景设计

## 目标

在仓库内新增一个独立、可运行的 MuJoCo 场景，用于之后加载机器狗并测试其触碰墙壁开关、电梯呼叫按钮和轿厢楼层按钮。场景同时支持鼠标点击实体按钮。环境模型不内嵌特定机器人，也不依赖机器人控制策略。

## 已确认的用户要求

- 房屋共三层，每层一个房间，三层房间的家具和装饰一致。
- 只保留房间后侧墙面；正面和左右两侧保持开放，以便从正面观察内部。
- 房屋右侧有电梯，房间仅通过本层电梯入口连接电梯。
- 每层有一盏安装在顶面的灯和一个墙面开关；灯在初始状态为开启。
- 电梯提供楼层呼叫按钮和轿厢内楼层按钮，初始停在三层。
- 交互按钮按人类站立操作高度布置，按钮中心离本层地面约 1.1 m。
- 场景不包含 Go2；之后由用户的仿真流程加载机器狗。
- 鼠标点击和机器人真实碰撞都能操作实体按钮。

## 实现结构

场景由独立 MJCF 文件描述静态房屋、家具、电梯轿厢、楼层入口、可动按钮、灯、传感器、执行器和固定观察相机。另提供 Python 控制模块处理按钮边沿、灯光状态、电梯目标楼层及运动状态；运行脚本创建 MuJoCo 窗口并处理鼠标拾取。控制模块只依赖场景中稳定命名的关节、传感器和灯光，不依赖 Go2 的关节或控制接口，后续与机器人模型组合后仍可复用。

鼠标事件不直接切换灯或电梯目标。运行窗口用 MuJoCo 射线选择命中的按钮，并对该按钮的滑动关节施加短时按压力；机器人则通过碰撞压下同一按钮。两种输入最终都经过按钮位移阈值、回弹和去抖逻辑，再产生一次按钮事件。这样鼠标操作和物理接触都会显示按钮行程，也共用同一状态处理路径。

## 场景布局

使用米为单位，房屋正面朝向固定相机，房间后墙位于相机对侧，电梯布置在房屋右侧。三层按相同的平面尺寸和竖向间距排列。楼层板与房间顶面构成层间结构，前侧、左侧和右侧不添加完整墙面；右侧仅保留连接电梯所需的入口边界。

每层重复放置简化原语组成的家具和装饰，例如靠后墙的沙发、房间内的低桌、边角绿植和墙面挂画。物件使用独立碰撞几何，控制数量和尺寸，避免堵住右侧电梯入口。每层灯安装在顶部板下方，开关位于后墙内侧、约 1.1 m 高。低环境光用于让灯的开关产生清晰可见的明暗变化。

电梯位于房屋右侧，使用沿竖直滑轨运动的平台和开放式轿厢结构，让观察相机能看到轿厢和房间。平台在三个楼层高度之间平滑移动；停靠时平台表面与楼层板齐平。每个入口设置不遮挡房间正面视线的简化门扇或挡板：仅当前停靠楼层开放，电梯离开后关闭，避免机器人误入空井。入口旁布置楼层呼叫面板，轿厢内布置 1–3 层按钮。底层提供上行呼叫，中层提供上下行呼叫，顶层提供下行呼叫。门扇只服务安全通行，不延伸成房间墙面。

房间灯开关、入口呼叫按钮和轿厢楼层按钮都以实体可动按钮表示，中心高度均为约 1.1 m。按钮沿面板法向滑动，带回弹和限位；名称、材质和颜色用于区分楼层、方向及灯光用途。

## 状态与交互

- **灯光：** 三层分别维护独立开关状态，初始都为开启。检测到一次完整按压后翻转对应楼层的灯；持续接触只产生一次事件，按钮回弹后才允许下一次按压。
- **呼叫电梯：** 楼层呼叫事件请求轿厢到达该楼层。方向按钮会记录并显示期望方向，控制器将轿厢驶向呼叫楼层，并在停靠时开放该层入口。
- **选择目的层：** 轿厢内楼层按钮将楼层加入服务请求。控制器逐一处理请求，合并重复楼层请求；新请求不会突然改变正在执行的物理行程。
- **电梯运动：** 控制器通过限速的位置目标驱动竖直滑台。离站时先关闭原楼层入口，停靠并确认平台对齐后开放目标楼层入口。场景重置时轿厢位于三层，三层入口开放。
- **鼠标操作：** 单击可见按钮时，运行脚本将鼠标按压映射到该按钮的物理滑动行程，随后松开并回弹。按钮不存在鼠标专属的直接业务捷径。
- **机器人操作：** 任何机器人碰撞实体按钮并使按钮位移超过阈值时，都产生同样的按压事件。环境本身不生成或控制机器人。

控制器对按压和回弹采用不同阈值，避免接触边缘产生重复触发；按压事件只在按钮从未按下变为按下时产生。灯光直接关联 MuJoCo 灯光启用状态，电梯目标与入口门状态由显式状态机维护。

## 观察与运行

MJCF 内含固定正面总览相机，视野覆盖三层房间和右侧电梯，并略微俯视以展示家具和入口。运行脚本启动时默认使用该相机；用户仍可通过 MuJoCo 窗口调整视角。灯光使用简单材质与几何体，不依赖额外网格、纹理或外部资产。

场景文件放在 `simulate/mujoco/model/` 下的独立目录，Python 控制器、运行入口和简短使用说明与场景文件同目录。运行入口默认加载独立环境；后续组合机器人时，通过稳定名称查找按钮传感器和执行器，不要求修改电梯/灯光逻辑。

## 验收标准

1. MuJoCo Python API 能从仓库路径加载场景 XML，创建数据并连续步进，不出现编译或运行时错误。
2. 场景包含三层房间、三盏初始开启的灯、三套灯开关、右侧电梯、入口呼叫按钮、轿厢楼层按钮和固定正面相机；模型中没有机器人。
3. 重置后轿厢处于三层，平台与三层入口对齐，三层入口开放。
4. 场景可通过鼠标命中并按压按钮；每个可动按钮的关节位移及回弹均可见。
5. 用测试刚体按压按钮能触发同一逻辑：灯开关只改变对应楼层灯；呼叫和楼层按钮使轿厢停靠正确楼层并同步入口门。
6. 控制器单元测试覆盖去抖、灯状态翻转、呼叫请求、楼层请求排队、运动中入口关闭和停靠后入口开放。
7. 总览相机能在单一画面中观察三层和右侧电梯；三层家具和装饰一致，房间正面及两侧没有完整遮挡墙。

## 范围边界

本设计不包含机器狗模型、机器狗导航策略、训练任务或奖励函数；不尝试仿真乘客、安全认证或真实电梯动力学。电梯采用可预测的受控竖直滑台，按钮仅提供环境交互所需的力学行程。
