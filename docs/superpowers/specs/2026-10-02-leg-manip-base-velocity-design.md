# leg_manip 基座速度观测改造

用户已确认采用统一锚点系基座线速度，并明确要求新实验从头训练，检查能否
晋级 stage 3。Actor/critic 随机初始化，不加载旧 checkpoint，课程从 stage 0 开始。
本设计落实此前速度观测分析，不修改速度奖励、晋级条件
或锚点 heading 算法；此前双足修复保留。

Actor 原 48 个通道保持顺序、缩放与噪声不变，在索引 48:51 追加
`2 * (to_anchor(term.basis_w, root_link_lin_vel_w) + noise)`。
noise 为每轴独立 `U(-0.02, 0.02)` m/s，play 不加噪。所有支撑模式和过渡
均输出速度，不使用高度或模式门控。Critic 保持 131 维，前 48 项仍共享
actor 原通道的噪声采样，48:51 改为同一锚点系速度乘 2 的精确值。
Actor 与 critic 速度的物理量、时刻、坐标系、顺序和缩放完全相同，仅噪声不同。

任务专用左右镜像在原 48 项镜像后，将新速度按 (+,-,+) 镜像。共用 PPO
增加可覆盖的对称损失方法，保持其他任务原有行为。LegManipPPO 验证 51/131
观测维度。现有 actor_sample 在 policy 调用中保存完整 51 维采样，critic
共享函数只返回原 48 维。

旧 checkpoint 的显式迁移工具仅用于兼容性验证或另行选择的 warm-start 实验，
本次正式实验不使用迁移后的权重。迁移生成新文件，原文件不覆盖。Actor 第一层追加
三个零权重列，使初始动作保持一致；critic 第一层 48:51 列除以 2，以补偿
精确速度缩放。清空 Adam 状态，保留参数组与学习率；保持 stage、迭代计数
和 common_step_counter，清空晋级统计窗口并从恢复时刻重新计最短阶段步数。
新 checkpoint 记录观测布局版本。

验证包括实际观测函数在水平/45°/直立和不同 yaw 下的值、噪声范围、精确值
及镜像；迁移前后 actor/critic 输出等价、原文件不变；真实 CPU 环境、PPO
更新、保存/恢复、ONNX 导出；最后 GPU 冒烟和正式训练。用户选择等待 4090
服务器开启后，使用 4096 个环境、seed 42，从随机初始化执行 15000 次更新。
设置 resume=False，不恢复模型、优化器、计数或课程状态；建立独立 run。
保留原晋级门槛并记录速度、足端、落脚和 stage 指标，不能把未晋级描述为晋级。
这轮同时包含已确认的双足修复，因此与历史 run 的比较不能单独归因于速度观测。
