# 三层开放房屋与可交互电梯

独立 MuJoCo 环境，不含机器狗或机器人策略。每层一个房间，重复布置长椅、桌子、绿植、挂画和顶灯；长椅有四条可碰撞的腿，三层的单人椅均已删除。长椅向右留出灯开关的接近空间。仅后墙可见。房屋右侧每层有一个与房间齐平相连的候梯平台，外侧连接带自动双扇门的电梯轿厢。电梯初始停在三层，轿厢门打开，三盏房间灯均开启。

![初始场景](preview.png)

## 运行

在仓库根目录、安装了 MuJoCo 的 Python 环境中执行。已验证环境为 Python 3.11、MuJoCo 3.5.0；依赖为 `mujoco`、`numpy`、`glfw` 和 `PyOpenGL`。浏览器服务使用 Python 标准库，不需要前端构建或 Web 框架。

桌面 MuJoCo 渲染窗口：

```bash
python simulate/mujoco/model/three_floor_elevator/run.py
```

浏览器模式：

```bash
python simulate/mujoco/model/three_floor_elevator/run.py --web
```

保持脚本运行，打开终端打印的地址，默认是 <http://127.0.0.1:8765/>。Linux 上默认使用 EGL 离屏渲染，无需 X11 窗口，但需要可用的 EGL/OpenGL 驱动。显式设置的 `MUJOCO_GL` 会保留。浏览器显示 MuJoCo 实时渲染画面。

从其他设备访问时，可用 `--web --host 0.0.0.0 --port 8765`，然后访问仿真机器的 IP 地址；远程开发环境也可转发 8765 端口。默认只监听本机。两个入口均支持 `--xml PATH` 加载保留相同对象名称的组合 MJCF。

- 左键点击实体按钮或其数字/箭头，对按钮关节施加短时压力。
- 右键拖动旋转，滚轮缩放。侧向安装的按钮可旋转后观察和点按。
- 黄色方形是墙上灯开关；绿色 ↑ 为上行呼叫，红色 ↓ 为下行呼叫；轿厢按钮标有 1、2、3。
- Web 页面的“重置场景”恢复初始状态。终端按 Ctrl+C 关闭 Web 服务。

## 布局和接触

单位为米。房间范围 x∈[-3,3]、y∈[-2,2]，后墙在 +Y，相机在 -Y，电梯在 +X。楼面高度为 **0、2.8、5.6 m**。三层候梯平台范围 x∈[3,4.82]、y∈[-1.6,1.2]，内侧与房间楼板相接。电梯中心 x=5.9、y=-0.2，到站时平台表面与楼面齐平，候梯平台和轿厢之间保留约 3 cm 的运动间隙。

原来的三块楼层移动墙已删除。两扇门安装在轿厢左侧并随轿厢升降，沿相反的 Y 方向滑入侧板后方，开启时形成约 1.3 m 净宽入口。轿厢有固定背板、顶板和透明正面/右侧板，既能碰撞，又方便观察内部。候梯平台设有透明护栏和呼叫面板；一楼平台的前侧留有进入候梯区的开口。

房间前面及两侧设置了**不可见碰撞边界**，渲染中保持开放；右侧通过候梯平台通行，楼层之间使用电梯。边界和部分家具简化碰撞体在 geom group 3，查看器默认隐藏该组，碰撞仍生效。座椅使用座面、靠背及椅腿自身的碰撞几何。其他查看器也可关闭 group 3 的显示。上层地板构成下层顶板，三层及其候梯平台另有屋顶。

一楼候梯区前有外部接近平台，机器人可以从楼外走入候梯区；一楼只保留候梯平台后侧的上行按钮。建议之后将机器人初始化在外部平台 x≈3.9、y≈-3.0，机身高度按模型设置。各层呼叫按钮位于候梯平台后侧，朝向 -Y；进入候梯区后可以沿 +Y 方向按压。

一楼外部入口平台靠房间的一侧设有可碰撞玻璃挡柱，中心为 (x,y)=(3,-1.8)，截面 20×48 cm、高 1.1 m，与候梯护栏等高。挡柱覆盖房间前沿到候梯区前护栏之间的缺口，两端略有重叠以封住接缝；外部平台入口及房间与候梯区之间的正常通道保持畅通。

灯开关、二三楼呼梯按钮和轿厢按钮中心距各自地面 **0.85 m**；一楼呼梯按钮保留原有 **0.62 m** 高度。灯开关可按面为 **20×20 cm**，底板为 30×30 cm；圆形按钮直径 **21 cm**，底板、箭头、楼层数字与指示灯随之调整。此尺寸让机器狗在约 0.75–0.85 m 的抬手高度接触按钮，同时保留墙面面板的外观。二三楼面板立柱减薄并后移，为活动按钮完整行程留出空间。

按钮按压主体保留原有质量和按压深度。行程 25 mm，压入超过 16 mm 触发，回弹至 6 mm 以下才能再次触发。机器人真实接触和鼠标共用同一事件路径。灯开关只改变本层灯；持续按住只触发一次。

呼叫和目的层按顺序排队、合并重复请求。离站前等待轿厢两扇门实际关闭且停稳；电梯运行中保持关门，到站并对齐候梯平台后自动打开两扇门，充分打开后至少停留 2 秒再处理后续请求。没有后续请求时持续开门。上下按钮分别显示呼叫状态，采用同一楼层服务队列，暂不按行驶方向优化调度。

## 后续组合机器狗

将环境和机器人合入**同一个 MjModel**，保留下列名称；在另一个模型中加载机器狗不会产生跨模型碰撞。可使用 `MjSpec` 或生成组合 MJCF，然后把同一 `model, data` 传给控制器。

| 对象 | 名称 |
| --- | --- |
| 房间灯 | `lamp_f1`、`lamp_f2`、`lamp_f3` |
| 灯开关逻辑名 | `light_f1`、`light_f2`、`light_f3` |
| 楼层呼叫逻辑名 | `call_up_f1`、`call_up_f2`、`call_down_f2`、`call_down_f3` |
| 轿厢按钮逻辑名 | `cab_f1`、`cab_f2`、`cab_f3` |
| 按钮实体 | `button_<逻辑名>` body、`joint_<逻辑名>` joint、`geom_<逻辑名>` geom |
| 电梯 | `elevator_car` body、`lift_z` joint、`lift_position` actuator |
| 候梯平台 | `lobby_f1..3` body、`lobby_floor_f1..3` geom |
| 轿厢双扇门 | `joint_car_door_front/back` joint、`car_door_front/back` actuator |
| 正面相机 | `front_overview` |

最小步进顺序：

```python
import mujoco
from simulate.mujoco.model.three_floor_elevator.controller import ThreeFloorElevatorController

controller = ThreeFloorElevatorController(model, data)
controller.reset()  # 重置整个 data；随后可设置机器人初始 qpos，再 mj_forward。
while running:
    # 只写机器人自己的 actuator 索引，保留电梯和门的 ctrl。
    controller.apply_mouse_forces()  # 同时维护轿厢自身重量补偿。
    mujoco.mj_step(model, data)
    controller.update()
```

机器人接触无需调用 `mouse_press`；该方法供鼠标界面使用。脚本也可用 `request_floor(1)` 请求停靠。控制器使用按钮及电梯自由度的 `qfrc_applied`，请保留这些项，避免在控制器调用之间将整个数组清零；机器人可对自己的自由度施力。

## 验证和范围

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest tests/test_three_floor_elevator.py -q
```

22 项测试覆盖候梯平台的连接、轿厢与门的世界坐标、整个升降行程的几何避碰、初始灯与门、按钮去抖、真实刚体触碰灯/呼叫/轿厢按钮、鼠标按压和拾取、排队与开门停留、运行时关门、上下行与中间层停靠、15 kg 载荷停靠和入口边界。禁用第三方 pytest 插件自动加载可避免本地 ROS 插件干扰。

电梯是带重量补偿及阻尼的理想滑台，位置目标按 1.5 m/s 限速；空载及 15 kg 载荷上下行测试检查实际速度不超过 1.6 m/s。不模拟真实曳引系统。家具采用原语和简化碰撞体；暂不包含机器人导航、按键策略或训练奖励，实际机器狗接入后仍需验证其接触与控制。
